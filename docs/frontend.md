# NextStop 프론트엔드 개발 안내

2026년 10월 15일 기준 React 웹 미리보기의 구현 상태입니다. 실제 교통 데이터·백엔드·모바일 알림 연동에 앞서 사용 흐름과 노선도 UI를 검토할 수 있습니다.

후속 개발은 사용자 결정에 따라 Android 전용·백엔드 없는 직접 조회 방식으로 진행합니다. 네이티브 구현은 `android/`에 있으며 [Android 개발 안내](android.md)를 따릅니다. 아래 React 웹에는 개인 키를 입력하거나 네이티브 API 호출을 추가하지 않았습니다.

## 실행과 명령

Node.js 22.12 이상 짝수 버전과 npm을 사용합니다. 이 환경에서는 Node.js 26.8.1로 검증했습니다.

```bash
npm ci
npm run dev
```

기본 주소는 `http://localhost:5180`입니다. 포트를 바꾸려면 `npm run dev -- --port 5181`을 실행합니다. 같은 포트가 사용 중이면 개발 서버는 자동으로 다른 포트로 이동하지 않고 종료합니다.

| 명령 | 용도 |
| --- | --- |
| `npm run dev` | React 개발 서버 |
| `npm run build` | TypeScript 검사 후 `dist/` 생성 |
| `npm run preview` | 빌드 결과 미리보기 |
| `npm test` | 상태·이벤트·저장 복원 단위 테스트 |
| `npm run test:e2e` | 데스크톱·모바일 브라우저 테스트 |
| `npm run capture` | 홈·내 이동·다크 설정 화면을 두 크기로 캡처 |

브라우저 테스트와 캡처는 실행 중인 개발 서버를 사용합니다. 최초 설치 후 `npx playwright install chromium`으로 브라우저를 준비합니다. 다른 주소는 `PLAYWRIGHT_BASE_URL`, 이미 설치된 Chromium은 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 환경 변수로 지정할 수 있습니다. 캡처 기본 경로는 `/tmp/nextstop-preview`이며 `NEXTSTOP_CAPTURE_DIR`로 바꿀 수 있습니다.

## 화면 구성과 동작

| 화면 | 주소 | 주요 동작 |
| --- | --- | --- |
| 노선 찾기 | `#/home` | 지역·버스/지하철·노선/정류장 검색, 최근 선택, 즐겨찾기 |
| 탑승 선택 | 노선 카드에서 대화상자 열기 | 방향·탑승·하차 지점과 알림 모드 선택, 차량 후보 확인 |
| 내 이동 | `#/ride` | 현재 위치·구간, 다음 지점, 이전/이후 각각 최대 3개, 남은 지점, 도착 기록 |
| 즐겨찾기 | `#/favorites` | 기기에 저장한 노선 검색·선택 |
| 알림 설정 | `#/settings` | 알림 모드, 소리·진동 설정, 화면 테마, 시스템 알림 화면 예시 |

노선도 양 끝에서는 존재하는 지점만 표시합니다. 이동 중에는 중앙에 이동 표시를 두고 현재 구간을 함께 표시합니다. 선택한 방향의 정차 순서를 기준으로 다음 지점과 하차까지 남은 지점을 계산합니다.

기본 알림 모드는 하차 알림입니다. 하차 알림에는 하차 지점 선택이 필요합니다. 모든 도착 모드는 각 도착과 하차 직전 안내를 생성하며, 무음 모드는 진행 표시만 갱신합니다. 설정 화면에서 모드를 바꾸면 현재 이동과 다음 이동의 기본 설정에 적용됩니다. 소리·진동은 설정 저장만 제공하며 실제 기기 동작을 발생시키지 않습니다.

현재 이동을 시작한 상태에서 새 차량을 선택하면 기존 이동을 종료한다는 안내를 표시합니다. 하차 완료는 확인 대화상자를 거친 뒤 활성 이동을 제거합니다. 하차 지점을 지나도 사용자가 완료할 때까지 해당 차량의 진행을 확인할 수 있습니다.

## 예시 데이터와 범위

| 예시 | 화면에서 가능한 기능 |
| --- | --- |
| 서울 2·9호선, 서울 271·경기 7770 버스 | 예시 차량 선택과 이동 체험 |
| 부산 1·대구 2·대전 1·광주 1호선 | 시간표 안내 화면의 정차 경로 예시 |

지역 필터에는 전국·서울·경기·부산·대구·대전·광주·인천을 제공합니다. 인천 예시 노선은 아직 없으며 검색 결과 없음 상태를 표시합니다. 실제 전국 노선 목록, 실제 시간표나 정류장 도착 예정 시각은 제공하지 않습니다. 예시의 `realtime` 값은 차량 추적 UI를 체험할 수 있는 종류를 뜻합니다.

차량번호와 열차번호는 생성한 예시입니다. 차량 식별·방향·후보 정보의 유효성을 검사하며, 90초를 넘긴 후보는 새로 조회해야 시작할 수 있습니다. 실제 운행 차량과 매칭했다는 의미는 아닙니다.

수동 버튼은 출발과 다음 지점 도착을 번갈아 진행합니다. 자동 진행은 6.5초마다 같은 상태 전이를 실행하고 종점에서 멈춥니다. 이는 실제 이동 시간·속도와 관계가 없습니다. 화면이 닫히거나 브라우저가 백그라운드 타이머를 제한하면 진행을 유지할 수 없습니다.

마지막 상태 갱신으로부터 90초가 지나면 갱신 지연으로 전환하고 진행을 중단합니다. 갱신 지연 보기와 정보 갱신하기 버튼으로 해당 흐름을 체험할 수 있습니다. 도착 이벤트는 이동 ID·지점 순번·이벤트 종류로 중복을 제거하고 최근 20개를 유지합니다.

Android·iOS 알림 미리보기는 웹 UI입니다. 브라우저 알림 권한 요청, 푸시, 서비스 워커, 위치 권한, Android 지속 알림과 ActivityKit을 연결하지 않았습니다. 모바일 앱의 실제 노출 형태는 [플랫폼별 알림 결정](development.md#플랫폼별-알림-결정)에 따라 별도 검증해야 합니다.

## 상태와 코드 구성

| 파일 | 역할 |
| --- | --- |
| `src/App.tsx` | 네 화면, 탑승 선택, 이동 제어와 설정 |
| `src/data/catalog.ts` | 예시 노선, 정차 순서와 차량 후보 생성 |
| `src/domain/types.ts` | 노선·차량·이동·설정 모델 |
| `src/domain/ride.ts` | 탑승 검증, 진행 전이, 주변 노선도와 도착 이벤트 |
| `src/state/store.ts` | 상태 저장·검증·복원 |
| `src/components/` | 노선 카드·노선도·시스템 알림 미리보기·대화상자·SVG 그림 |
| `src/main.tsx` | React 시작과 디자인 토큰 적용 |
| `src/styles.css` | 푸른색·상아색 테마, 반응형 레이아웃, 다크 모드 |
| `tests/journey.spec.ts` | 사용자 흐름 브라우저 검증 |

`localStorage`의 `nextstop.preview.v1`에 즐겨찾기, 최근 선택 최대 4개, 설정과 활성 이동 1개를 저장합니다. 복원 시 형식과 예시 노선 존재 여부를 검사합니다. 손상된 이동은 제거하며 유효한 즐겨찾기·설정은 유지합니다. 4시간을 넘긴 이동은 복원하지 않습니다. 이 4시간은 웹 체험의 만료 기준이며 네이티브 세션 수명은 개발 명세에서 별도로 정합니다.

디자인 색상의 원본은 `docs/design-tokens.json`입니다. 런타임에서 밝은 화면·어두운 화면의 CSS 변수로 적용합니다. 기본 블루는 `#2457C5`, 상아색 배경은 `#FFF8E7`이며 상세 HEX는 [UI 디자인 시스템](design-system.md)에 있습니다.

## 검증 결과

빌드와 TypeScript 검사, 단위 테스트 15개, Chromium의 데스크톱·Pixel 7·iPhone 16 에뮬레이션 브라우저 테스트 총 24개를 통과했습니다. iPhone 16 프로젝트는 개발자 도구의 기기 모드와 같이 Chromium에서 393×852 화면과 터치를 에뮬레이션합니다.

단위 테스트는 탑승 검증, 방향별 순서, 출발·도착 구분, 하차 전 안내, 알림 중복 제거, 무음·지연 상태, 종점과 저장 상태 손상을 확인합니다. 브라우저 테스트는 지하철·버스 탑승부터 종료, 상태 복원, 지역 검색과 시간표 안내 분리, 즐겨찾기·설정 저장, 280~768px 화면과 탑승 선택창의 가로 넘침, 좌우 터치 드래그 후 가로 위치 유지와 세로 스크롤, 대화상자 포커스 복원과 키보드 본문 이동을 확인합니다.

가로 넘침은 모바일에서 콘텐츠 폭에 따라 늘어날 수 있는 `innerWidth` 대신 `documentElement.clientWidth`와 문서·본문 폭을 비교합니다. 본문의 고정 최소 폭을 없애고 검색 조건은 공간이 부족하면 줄바꿈합니다. 페이지의 가로 넘침과 가장자리 오버스크롤을 제한하고, 터치에서는 세로 스크롤과 핀치 확대를 허용합니다.

이 결과는 웹 미리보기의 검증입니다. Safari, 실기기의 네이티브 알림과 실제 API의 정확도·지연·차량 매칭은 후속 검증 범위입니다.
